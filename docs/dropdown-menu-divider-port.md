## Detailed checklist audit

- **Single horizontal separator — closed.** The port delegates to the same unlabeled Divider defaults as the pin and exposes no size, color, orientation, or label variants. The showcase matches the pinned **MenuSeparator** story's trigger label and row order, including destructive Delete. This is a source comparison, not a rendered upstream comparison.
- **Compound semantics and arrow traversal — verified.** The focused Chrome suite from PR #241 (merge `5f3a872`) opened the menu with ArrowDown, verified focus went Edit → Delete → Edit with Down/Up, and confirmed that calling `.focus()` on the separator did not focus it. It checked the DOM role and horizontal orientation, no `tabindex`, and an unnamed AX separator, plus the default 4px block margins and 1px full-width rule at the tested configuration. The pinned `DropdownMenu.test.tsx` (`ffeb32fb440c952406101b69aa66fdddec133c20`) asserts the same forward traversal contract. That pinned test was reviewed, not run here.
- **Pointer data/compound parity — blocked on the menu owners.** The pinned DropdownMenu, ContextMenu, and BreadcrumbItem route pointer data through `renderDropdownItems`, whose divider branch renders `DropdownMenuDivider`. The pinned parity test compares data/compound `outerHTML` and the menu target class. The Rust owners currently expose only compound menu content, with no typed `{type: 'divider'}` entry point. Those owners must first expose pointer data inputs and route divider entries through this component, then verify equivalent DOM, spacing, semantics, and both target classes. Compound alias equality does not prove data parity. Touch and bottom-sheet data dividers stay with the parent surfaces.
- **Host inputs and styling — partially verified.** All four focused Rust tests passed. SSR verifies alias equality, compound placement, both theme classes, caller ID/data/ARIA/class/inline style, and rejection of mixed-case role, orientation, and focus overrides. The VirtualDom test registers click and mount on the same element and dispatches a synthetic runtime click there. This does not prove native click delivery or that `onmounted` resolves to the real separator element. The existing `class`/inline `style` inputs adapt caller `xstyle`; no StyleX prop or visual variant is needed. The integrator's browser follow-up needs a caller-input fixture that checks native click delivery, mounted-element identity, and computed block margins with a caller spacing override, while preserving role/orientation and the theme targets.
