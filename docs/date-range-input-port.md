# Date Range Input: native endpoint checkpoint

`src/date_range_input/` composes two existing Date Inputs in a named fieldset. Callers own the committed range. Either endpoint can be entered first. Both dates must be present, ordered, and within the inclusive bounds before the component emits a range. Clearing an endpoint of a committed range requests clearing the range. A reversed or out-of-bounds draft shows one status message without emitting a new value. Both date controls reference that message and expose `aria-invalid`; these attributes clear when the range is corrected. This does not change native constraint validation.
