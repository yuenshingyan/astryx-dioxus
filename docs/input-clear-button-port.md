# InputClearButton checkpoint

The Field-owned clear button is used by `TextInput { has_clear: true }` when the value is nonempty and editable. It passes the caller’s contextual name through unchanged and uses the shared ghost Button with a separate, localized tooltip (`@astryx.inputClearButton.tooltip`, English fallback “Clear”). It cancels non-touch `pointerdown` and all `mousedown` defaults to avoid taking focus; touch `pointerdown` is deliberately left uncancelled so WebKit can produce the click. Native activation invokes the existing callback. TextInput owns the controlled value and focus: clearing requests an empty string through `on_change` and focuses the input. It does not synthesize a DOM `input` event. The opt-in search field hides the browser's duplicate clear affordance where supported.

Sources at Meta Astryx `476a3153417dbf75c565f7df05b0784e94ddd59e`: `Field/InputClearButton.tsx` (`750b7a288f6ba6e0aa494bf17888ba30dc3fd703`) and `TextInputSearch.tsx` (`47eeb2647803915f6df5c82fd55c6d8fdaccfed6`). The Search showcase adapts the empty and prefilled arrangements.

Before this follow-up, all five Rust checks and four Chrome suites passed. Chrome verified the button’s accessible name, its omission for empty, disabled and read-only fields, keyboard and mouse activation, and focus retention or return. The new focused SSR test covers the native button, decorative glyph and separate contextual name/tooltip in fallback English and French. The updated Chrome test is for integrator verification: it covers DOM/AX naming, synthetic event cancellation, Tab/Enter/Space and real Chrome mouse input. Synthetic pointer dispatch does not prove native touch activation or iOS software-keyboard retention.

Remaining gates:

- The popup-aware variant needs a layer-trigger owner to supply the keep-open pointer-down and click-capture behavior. Shared Button press hit testing also needs a per-clear growth hook to clamp to half the sibling gap and at most 2 px toward a beside-part. The generic Button band does not do that for decorative siblings. These are shared-owner follow-ups, not CSS-only changes.
- Existing field owners still compose their own labels; a localized tooltip alone does not make every caller’s label satisfy label-in-name. Public export and upstream caller styling seams would change the Rust API and need approval.
- Painted parity is unverified. The 20 px height override is TextInput-scoped, unlike the pinned source’s primitive-level rule; the icon target’s secondary-color stylesheet declaration competes with Icon’s inline `color:inherit`. Check computed paint and geometry across hosts separately from raster comparisons. Spoken output and iOS software-keyboard retention require manual device/AT checks; Chrome DOM/AX does not establish them.
