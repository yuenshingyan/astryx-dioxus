## Evidence by checklist item

- **Axis and inline display:** The bundled selectors and SSR reflection match the pinned flex rules. `Horizontal` sets main-axis `justify-content`; `Vertical` sets cross-axis `align-items`; `Both` sets both. This preserves the FR2 gap: in vertical writing the single-axis names do not denote physical axes. The default is block-level flex; the inline modifier uses `inline-flex`. The showcase now includes explicit vertical-only and inline examples.
- **Padding:** The eleven supported values match the pinned spacing tokens. Source and SSR confirm per-edge resolution (edge → axis → uniform), explicit zero, and no publication of container-padding variables. The bundle uses logical properties, not physical side names.
- **Sizing and semantics:** SSR verifies numeric pixels, CSS values, native child order, no added role/name/tab stop, and caller opt-in to root semantics. CSS-wide keywords such as `inherit` now apply to the dimension itself instead of to an intermediate custom property. Same-layer classes preserve the caller's existing class and inline-style override paths. The combined detailed item remains open until this fix is checked in the browser.
- **Templates:** Horizontal Center uses the pinned 520px Card and six named, small ghost formatting controls; the writing-mode caveat is now shown alongside it. Inside a Card uses the pinned 400px Card, 200px Center, Inbox icon, bold body text (not a semantic heading in the source), and supporting description. Center uses the pinned full-width 240px box and level-four heading. All three render in the focused SSR suite. This verifies recipe composition, not every dependency's behavior or published pixels.

## Remaining closure evidence

The previous Chrome run compared the three Rust patterns to clones with source-derived flex declarations. It did not run upstream React/StyleX, measure independent dependency paint, or compare published screenshots. The updated browser test is syntax-checked but not executed. On a preview, run `SHOWCASE_URL=http://127.0.0.1:8114 node tests/center.browser.mjs` with a Chrome CDP endpoint on port 9222. It now also checks computed inherited width/max-width/min-height, inline display, and cross-axis/padding mappings in horizontal and vertical writing with LTR and RTL.

For visual closure, compare the three patterns with rendered upstream templates (including Card, Stack, Icon/IconButton and typography framing), rather than clones. The four pinned `core-center--default` Neutral/Probe light/dark PNGs were downloaded and checked against both the Git tree and visual manifest; they depict the separate `Default` Storybook fixture, so compare them against a matching Rust fixture, not the CLI showcase. Manual AT evidence is also missing: verify no added focus stop or landmark, native reading order, and the formatting buttons' names in the rendered showcase. FR6 uses Dioxus root attributes and `onmounted` instead of React `ref`, and `class`/`style` instead of StyleX `xstyle`; live root event/mount reachability and override precedence have not been verified here. Literal React/StyleX API parity would require an explicit acceptance decision for these adapters, not a change to the existing Rust API in this pass.

The full Rust suite, clippy, and the WASM showcase build were not rerun. No browser or preview was started for this audit.
