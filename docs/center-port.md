## Source and scope

This audit used [Meta Astryx `476a315`](https://github.com/meta/astryx/tree/476a3153417dbf75c565f7df05b0784e94ddd59e). Git blob hashes matched the pinned tree for `Center.tsx` (`4e2c74dac91ee1e66e6edfd540936f0b5da35358`), `Center.spec.md` (`29bd13dfa191340f6111664ea524b28b33656579`), the English docs and upstream tests, and all three CLI templates and their metadata. The audit also verified `BaseProps`, `mergeProps`, `themeProps`, the naming helper, shared size/spacing types, Layout's padding modules, theme tokens, and the Card, Stack, Icon, IconButton, Text and Heading sources used in the patterns. The pinned package lock resolves Heroicons 2.2.0; all seven local glyph paths match the corresponding outline SVGs in that tag.

## Evidence by checklist item

- **Axis and inline display:** The bundled selectors and SSR reflection match the pinned flex rules. `Horizontal` sets main-axis `justify-content`; `Vertical` sets cross-axis `align-items`; `Both` sets both. This preserves the FR2 gap: in vertical writing the single-axis names do not denote physical axes. The default is block-level flex; the inline modifier uses `inline-flex`. The showcase now includes explicit vertical-only and inline examples.
- **Padding:** The eleven supported values match the pinned spacing tokens. Source and SSR confirm per-edge resolution (edge → axis → uniform), explicit zero, and no publication of container-padding variables. The bundle uses logical properties, not physical side names.
- **Sizing and semantics:** SSR verifies numeric pixels, CSS values, native child order, no added role/name/tab stop, and caller opt-in to root semantics. CSS-wide keywords such as `inherit` apply to the dimension itself instead of to an intermediate custom property. PR #241's focused Chrome suite verified that computed `width`, `max-width`, and `min-height` match the explicitly sized parent in the `inherit` case.
- **Templates:** Horizontal Center uses the pinned 520px Card and six named, small ghost formatting controls; the writing-mode caveat is now shown alongside it. Inside a Card uses the pinned 400px Card, 200px Center, Inbox icon, bold body text (not a semantic heading in the source), and supporting description. Center uses the pinned full-width 240px box and level-four heading. All three render in the focused SSR suite. This verifies recipe composition, not every dependency's behavior or published pixels.

## Remaining closure evidence

PR #241 passed all eleven integrated Chrome suites, including `tests/center.browser.mjs`, and full CI. The Center suite verified inherited dimensions, inline display, and flex-axis and logical-padding mappings in horizontal and vertical writing with LTR and RTL. It compared the three Rust patterns to clones with source-derived flex declarations and checked the formatting buttons' DOM label attributes. It did not execute upstream React/StyleX, compare independent paint or pixels, or verify screen-reader output.

- **Rendered upstream comparison:** The four `core-center--default` Neutral/Probe light/dark PNGs match the pinned Git blob IDs and the visual manifest's SHA-256 hashes; all are 1024 × 768. The showcase's `#center-story-default` fixture corresponds to pinned [`Center.stories.tsx`](https://github.com/meta/astryx/blob/476a3153417dbf75c565f7df05b0784e94ddd59e/apps/storybook/stories/Center.stories.tsx) (blob `fdf5834a05145a6ec6ef9abb7c8ea382d5e82fed`): a full-width muted Section, a full-width 200px Center, and the token-styled “Centered Content” box. Capture this fixture in isolation with the upstream viewport, framing, typography, theme and color mode; the surrounding showcase and the 240px CLI recipe are not comparable. Probe requires an equivalent test theme, including its token and component overrides and typography; selecting dark mode on Neutral is not a substitute. The three CLI recipes still need independent rendered upstream references for Card, Stack, Icon/IconButton and Text/Heading framing and paint. Source comparison or SSR alone does not verify any pixels.
- **Manual AT:** In the rendered showcase, tab through the six formatting buttons and confirm there is no additional Center focus stop. Use screen-reader navigation to verify caller reading order, no extra Center landmark, and the spoken button names Bold, Italic, Underline, List, Link, and Image. SSR and the Chrome DOM label assertions are not an accessibility-tree (AX) inspection or speech evidence.
- **Live root adapters (FR6, verified for the Rust API):** PR #243's Chrome run verified that `onmounted` marks the root `div` with the caller attributes and protected `data-axis` (DOM), a native click reaches that root callback, and the width prop, caller class and caller inline style win in order (computed CSS). This does not establish literal React `ref`/StyleX `xstyle` API parity; any requirement for that needs a compatibility decision.

The prior focused audit passed six SSR tests. The new Storybook fixture's focused SSR test passed through `cargo-slot`: it verifies the muted Section, Center sizing and axis, and the caller box's markup and style declarations. It does not measure computed CSS, inspect AX, or compare paint. No browser or preview was started, and integrated CI was not rerun locally.
