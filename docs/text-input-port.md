# TextInput checkpoint

`src/text_input/` composes Field with a controlled native input. It supports text, password, email, search, telephone, and URL types, a decorative start icon, inherited size, and linked descriptions and status messages. Disabled inputs stay focusable and are omitted from form data; read-only inputs still submit.

Sources at Meta Astryx `476a3153417dbf75c565f7df05b0784e94ddd59e`: `TextInput/TextInput.tsx` (`1238f45e2d9550e7fee049812637dba586f33665`) and its spec (`81265924d60251b6add6c4a2befbb5b3fa63d4ed`). The showcase adapts parts of Showcase, Types, and States. The opt-in [clear action](input-clear-button-port.md) is available. The caller can set `is_loading` to expose `aria-busy` and show a decorative spinner before Clear. Editing and clearing remain available. The local search example simulates loading without a request. InputGroup integration, async action handling, loading announcements, disabled-reason help, and the remaining catalog arrangements stay open.

The attached-status follow-up implements the control glyph from FR9/AR4. It reuses the existing FieldStatus artwork and renders a decorative, severity-specific icon after the spinner and Clear slots, including when an attached status has no message. Detached messages still own their glyph. The native `aria-invalid` and message description associations, and the caller-owned loading policy, are unchanged. An error without explanatory text and a detached status without a message remain known accessibility gaps; tooltip status and the remaining FR16 keyboard hints are still open.

Formatting and bundle verification passed; no browser, visual, or spoken-output verification was run for this change.
