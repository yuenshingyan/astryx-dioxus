# Slider: single-thumb checkpoint

`src/slider/` uses a controlled native range input with FieldLabel, horizontal and vertical axes, and caller-supplied bounds and step. The browser owns value snapping and the default keyboard behavior except for PageUp and PageDown. `on_change` reports input events; `on_change_end` reports change events. After a committed interaction, the input reconciles to the caller's value, including when the caller rejects a change. Disabled sliders are excluded from form submission.

## Ten-step Page keys

Pinned `Slider.tsx` and `Slider.spec.md` (AR1) specify ten steps for PageUp and PageDown regardless of direction or orientation. The Slider's existing input controller overrides only those keys. It uses the range input's `stepUp(10)` and `stepDown(10)`, so the native step grid, bounds, and form value remain in force. A changed value dispatches `input` followed by `change` through the existing controlled callbacks and rollback path. At a bound, an unchanged value does not emit events.

`tests/slider.browser.mjs` now covers horizontal RTL and vertical Page steps, clamping, formatted accessible text, native form values, and rollback when the owner does not accept the step. The browser coverage was added but not run for this follow-up. This does not implement FR5's owner-rendered `on_change_end` payload or override native Home/End behavior for off-grid bounds.
