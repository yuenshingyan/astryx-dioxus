# File Input: native picker checkpoint

`src/file_input/` uses a native file input with Field. Callers can supply attached or detached status messages, which are associated with the input alongside its description. Error status sets `aria-invalid` without changing native validation. The browser owns the selection and form behavior; the callback hands Dioxus file handles to the caller without reading or uploading their contents. `accept` is a picker hint, not file validation.

## Busy keyboard guard

The pinned `FileInput.tsx` cancels Enter and Space on its focusable trigger while busy; the spec preserves that trigger's accessibility contract. This port applies the busy guard to the existing native input. It leaves Tab and idle keyboard behavior to the browser and keeps the input enabled so loading does not remove the selected file from the form. Explicitly disabled fields still use native `disabled`; the upstream focusable disabled trigger and disabled explanation remain open.

The focused SSR test checks that loading keeps native form participation and leaves the control in the Tab order. The browser suite now checks synthetic Enter, Space, and Tab keydowns in loading and idle states. The browser assertions were not run for this follow-up; OS picker behavior and real keyboard focus traversal remain unverified.
