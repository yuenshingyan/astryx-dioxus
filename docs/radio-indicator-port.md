# RadioIndicator port

`RadioIndicator` is the decorative visual for a caller-owned selection, not a form control. Both states retain the circle; checked adds a dot unless the caller supplies replacement content. The root owns `aria-hidden` and the reflected size and state, and forwards native attributes, styles, and callbacks. Keep role, name, focus behavior, and focusable content on the owner, not in the hidden subtree.

## Audit and remaining evidence

- **State and chrome:** The enum requires checked or unchecked with no partial state. SSR verifies a persistent empty unchecked span and the canonical checked dot. The circle and dot both use literal `50%`, as in the source, not `--radius-full`. The checked-medium source example now renders in the showcase and is covered by SSR.
- **Geometry and paint:** Source and port CSS agree on the 20/8px and 24/10px geometry, semantic border/fill/dot tokens, visual-only disabled opacity (`0.5`), and disabled border/unchecked fill (FR5). PR #241's focused Chrome suite confirmed the small circle/dot width, default medium circle, explicit checked-medium circle/dot geometry at `--radius-full: 0px`, and enabled/disabled opacity. It verified that a marked, hovered showcase ancestor tints the enabled unchecked fill and border, the enabled checked border, and the disabled checked fill without tinting its muted border; removal of the marker restores the baseline. The pinned primitive has no separate `:active` paint; the pressed layer belongs to RadioListItem. Rust RadioListItem mounts the indicator directly but does not set the equivalent hover marker. That host integration is not covered by the synthetic showcase scope. A matched raster comparison of Rust and pinned upstream in light/dark, enabled/disabled, and rest/hover remains open; the supplied source/spec files are not rendered upstream captures.
- **Replacement:** `None` retains the state mark; `Some(Element)` deliberately replaces it even when the element or container renders nothing. SSR covers explicit empty content, an empty element, nonempty text, and `0`. This is not full React `isRenderable` parity: the existing API has no separate raw boolean/nullish slot, and an explicitly supplied empty `Element` (including one made from an empty string) is still an intentional replacement. The shared Rust `is_renderable` walks virtual fragments and would reject some deliberately empty replacements. A change to the public empty-replacement contract would need an API decision; callers should use `None` for absent content.
- **Decoration:** SSR verifies protected `aria-hidden` and no component-generated role, input or tab stop. Unlike the pinned FR3 prop type, the existing native attribute API permits caller-supplied `role` and `tabindex`; narrowing it requires approval. Browser and manual AT verification with a real host are still needed: check tab order, a visible keyboard focus ring (including in forced colors), and one announcement of the host's name and applicable selected/disabled state without a duplicate indicator. The focused Chrome run confirmed a `0s` transition duration with reduced motion and distinct computed dot/fill colors under forced-color emulation. It did not capture pixels, test the real host's focus ring, or verify speech.
- **Restyle an indicator (the common path):** The Rust recipe uses scoped author CSS on the canonical `astryx-radio-indicator` and `astryx-radio-indicator-dot` targets (FR6), not a registry replacement. The pinned family recipe uses a 2px radio border and 2px dot radius; its checked+disabled override is on the checkbox, which the Rust example adapts to demonstrate radio state selectors. PR #241's Chrome suite confirmed the 2px borders, 2px dot radius, and disabled checked fill matching the muted token and differing from the enabled checked fill.
- **Replace an indicator with your own component:** The pinned recipe installs a token-styled **checkbox** and uses shallow `isRenderable` to prioritize pending content. This is not a third radio state. Rust has no equivalent theme indicator registry or host resolution; the upstream recipe is documented here, not claimed as a port.
- **Use radio visuals for single selection:** In the pin, `defineTheme({indicators: {check: RadioIndicator}})` makes existing check slots draw both checked dots and unchecked circles. Replacing `radio` itself is a separate key; CSS styling is not either replacement. Rust lacks both name-based replacements and the host resolution path (e.g. Selector) needed to demonstrate them. Mounting RadioIndicator directly does not verify this recipe.
