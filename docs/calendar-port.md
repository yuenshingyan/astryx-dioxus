# Calendar: single-month Gregorian checkpoint

`src/calendar/` renders a controlled single-date selection in a Sunday-first Gregorian grid. The caller supplies the initial visible date and can set inclusive minimum and maximum dates. Month buttons change the visible month without moving focus away from the button. One day in the visible month is tabbable. Arrows and Home/End move focus without changing selection, including across month boundaries. PageUp/PageDown move by a month; Shift with either key moves by a year. Paging clamps to the target month's last day and leaves the current focus unchanged if the result is outside the configured bounds. Enter or Space activates the focused day through its native button.

## Selection naming follow-up

The focused day button now includes “selected” in its accessible name when it matches the controlled `value` (upstream AR1). The gridcell still carries `aria-selected`, and unselected days keep their date-only names. This follows the existing English date-label path; localized date and selection labels are not ported. The existing bounded showcase already demonstrates changing selection. SSR tests cover selected and empty states; the browser suite now also checks the initial accessible name and that Enter transfers the selection suffix to the new date. Those browser assertions were not run in this follow-up.

**First-weekday blocker:** Upstream `weekStartsOn` accepts a Sunday-based index or a three-letter weekday name and controls weekday headers, date placement, and the week used for Home/End. Adding a defaulted Rust prop would still add a field to the exported `CalendarProps`, breaking existing struct literals and exhaustive destructuring. No existing Calendar prop carries this setting, and a new wrapper/provider would require approval. The Sunday-first header, grid, and Home/End behavior are unchanged.

Configurable first weekday, range selection, custom date constraints, multiple months, outside-day and week-number options, variable row counts, disabled-day focusability, localization and calendar systems, Date Input integration, and visual parity remain open. The checklist remains open.
