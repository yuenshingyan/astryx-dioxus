## Shift+wheel follow-up

The existing Carousel scroller owns a non-passive wheel listener only while its content overflows, using the same greater-than-1px threshold as its tab stop. It removes the listener when content fits again or the controller is torn down. Following the non-paging path in pinned `Carousel.tsx`, it leaves already-handled events, unshifted wheel input, horizontal trackpad input, and zero vertical deltas alone. For Shift+wheel with only a vertical delta, it prevents the native default without stopping propagation and passes the raw `deltaY` to horizontal `scrollBy({behavior: 'auto'})`. It does not reverse the physical delta in RTL or release the event at an edge while the row still overflows. The browser handles clamping and any existing CSS snap; the existing scroll observer still updates fades, buttons, and edge focus behavior.

`node tests/carousel_wheel.mjs` passed against the production controller with simulated DOM and observer boundaries. It covers listener registration/removal as overflow changes and on teardown, input filtering, raw deltas, and consumption at exhausted edges. The showcase points to existing non-snapping LTR and RTL rows for manual comparison. Formatting, CSS bundle verification, the renderer-independent library check and Clippy, and the wasm showcase type check also passed.

No preview, browser test, or full suite ran for this follow-up. Real wheel/trackpad defaults, native snap settling, and edge focus during wheel scrolling remain unverified in browsers. The scroller CSS was left unchanged, so `auto` follows the port's existing scroll behavior rather than importing upstream's smooth CSS default. Looping, touch parity, snap paging, imperative control, and broader visual parity remain open.
